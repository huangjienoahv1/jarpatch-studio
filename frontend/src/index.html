快速入门

          
JarPatch Studio 提供本地改包和运行时诊断。可导入 Jar、Spring Boot Jar 或 War 进行反编译和修改，也可在「运行时工作台」连接本机、远程 Windows/Linux 宿主机、Docker 或 Kubernetes 中的 Java 进程。

          
          
          
          
例如修改 Spring Boot 的 application-dev.yaml，可直接从 extracted/BOOT-INF/classes 打开文件，保存后点「差异」确认再导出，无需编译。所有导出均写入新路径，不会覆盖原包。

        


        

          
工作台与快捷键

          
          
    
            
  • 顶部操作栏分为三组：左侧为当前项目的核心工作流（分析、编译、差异、导出）；中间为扩展与维护入口（运行时工作台、仅管理员可见的 开发能力、以及收纳了项目设置/历史/清理/排错/诊断的 更多 下拉菜单）；右侧为 深浅色主题切换、帮助 与 账号菜单。
    • 
            
  • 左侧项目栏支持导入包、按关键词筛选历史项目，收起后仍可通过左上角 + 快捷按钮打开新包。
    • 
            
  • 中间工作区支持拖拽文件树与编辑器之间的分隔条调整宽度；右侧「分析与风险」默认收起为窄按钮，不挤占代码视野。
    • 
            
  • 底部状态栏集中展示 Java 智能状态灯、光标行列号、当前文件语言、资源文件编码切换与当前登录用户。

登录、账号与权限

          
软件采用本机离线账号认证，密码经 PBKDF2-SHA256 加盐后保存在本地 SQLite 中。首次启动会自动预置默认管理员 admin（初始密码 Admin@123），登录页会显示提示并支持「一键填入默认管理员」，首次登录后必须立即修改密码。

          
    
            
  • 会话与安全：勾选「保持本机登录状态」可保持 7 天有效；同一账号连续输错密码 5 次将锁定 60 秒。
    • 
            
  • 右上角账号菜单：普通用户可使用「修改我的密码」和「退出登录」；管理员额外可见「用户管理」入口。修改本人密码后会同步吊销该账号在其他会话中的登录态。
    • 
            
  • 本地用户管理仅管理员：支持按关键词、角色与状态筛选账号，新增本地用户、修改显示名/角色/启停状态、重置临时密码及删除账号。禁用账号或重置密码会立即吊销目标用户的所有活跃会话。

打开 Jar/War 与历史

          
    
            
  1. 点击左侧「打开 Jar / War」（或空状态页按钮、收起态左上角 + 按钮），选择本地普通 JAR、Spring Boot JAR 或 WAR 文件。
    2. 
            
  2. 程序先预解析包内的 pom.xml 与嵌套依赖。在「选择需要反编译的 Jar」弹窗中，可使用顶部搜索框按名称、路径或推荐原因实时筛选，通过「推荐选择 / 全选 / 清空」快速调整范围，右侧角标实时显示已选数量。
    3. 
            
  3. 点击「开始导入」执行解压和 CFR 分批反编译（自动跳过 module-info.class）。任务进行期间可随时点击任务栏的「取消任务」。
    4. 
          

          
左侧项目历史列出已导入的本地项目，支持输入关键词实时筛选。管理员点击删除按钮时，弹窗提供三选操作：仅删除历史（保留磁盘工作区，后续可在「扫描孤立工作区」处理）、预览并清理工作区后删除，或取消。存在运行中任务时不能删除项目历史。

          
多模块 Spring Boot 包的业务代码通常位于 BOOT-INF/lib/*.jar（War 包在 WEB-INF/lib/*.jar）。只改主包配置时可缩小反编译勾选范围以加快导入；若找不到某业务模块源码，检查导入时是否勾选了对应嵌套 Jar。

        


        

          
文件浏览、编辑与预览

          

            
文件树（sources 与 extracted）

            
sources 存放反编译得到的 Java 源码，主包源码按包名展开，勾选的嵌套 Jar 源码位于 sources/nested-jars/原相对路径/...；extracted 为解压后的原始包内容，文本与配置文件可直接编辑，二进制与签名文件只读展示。

            
文件树效率工具与搜索

            
文件浏览器右上角支持开启/关闭 包路径合并（默认开启，将单层目录合并为如 com.example）和 折叠所有目录。上方搜索框支持按文件名或内容检索，结果自动高亮关键字，点 × 可清空搜索返回完整文件树。

            
多文件标签栏与路径复制

            
打开多个文件时会在编辑器顶部形成标签栏，方便快速切换；存在未保存修改的文件会显示橙色圆点。路径面包屑旁提供「复制当前文件相对路径」按钮。

            
编码切换与保存

            
文件编码选择器位于窗口右下角 IDE 状态栏。Java 源码固定按 UTF-8 保存与编译；无 BOM 的资源文件出现乱码时，可显式切换为 GBK、GB18030、UTF-16LE/BE 重新打开。按 Ctrl+S（macOS 为 ⌘S）或点「保存」写入工作区，保留原有 BOM 与换行符，且外部内容变更时会阻止误覆盖。

            
中文预览（Unicode 转义解码）

            
遇到 \u7535\u5b50 等中文 Unicode 转义时，点击编辑器工具栏「中文预览」打开独立的只读 Monaco 预览视图。预览保留语法高亮、折叠与深浅主题联动，自动高亮解码区间，支持「上一处 / 下一处」定位和滚动位置双向同步，且不修改原文件；点「返回原文」继续编辑。

            
Java 代码智能与 AI 辅助

            
在「开发能力」启用 Eclipse JDT LS 后，支持补全、悬浮文档、跳转定义、实时诊断波浪线，以及工具栏的「快速修复」和「整理 import」。启用 AI 代码助手后，可按 Alt+\ 或点「AI 补全」触发一次行内建议，或打开「AI 助手」执行解释、按诊断修复与按要求重构；AI 解释仅只读展示，代码改动必须先在预览区核对后手动点击「应用修改」再保存。

          

        


        

          
分析与风险

          
点击顶部「分析」刷新当前项目的结构报告。点击右侧「分析与风险」窄条展开抽屉，可查看包类型、入口类、Manifest、class 数量、依赖数量、风险清单以及 已修改文件列表（点击可直接打开对应文件）。

          
    
            
  • 签名文件风险：存在 META-INF/*.SF、*.RSA 等签名文件时，修改任意 class 或资源都会导致原签名失效，导出阶段须按策略处理。
    • 
            
  • 嵌套 Jar / 多版本 / 混淆迹象：存在 META-INF/versions 多版本目录或明显混淆特征时，修改源码和重新编译前请重点核对对应类与运行环境。
    • 
          

        


        

          
编译

          
    
            
  1. 保存已修改的 Java 文件后点击顶部「编译」。后端会自动读取对应原始 .class 的版本号，严格匹配本地 JDK 并使用 --release 编译。
    2. 
            
  2. 为避免 Windows 命令行超长（CreateProcess error=206），编译器固定采用 javac @参数文件 调用，并显式传入 -proc:none（不自动运行原包依赖中的注解处理器）。
    3. 
            
  3. 编译产物先写入独立 staging 目录，全部目标通过后才统一写回主 classes 目录或对应嵌套 Jar；若写回阶段发生异常会自动恢复备份。
    4. 
          

          
系统不会自动改写你的业务源码。若反编译代码因混淆、泛型擦除或依赖 Lombok/MapStruct 等注解生成逻辑而报错，请先看底部「执行日志」的首条编译错误，再手动修正或改用原项目源码构建。

        


        

          
差异确认与导出

          
查看差异：点击顶部「差异」对比当前工作区与导入时的固定基线，按「源码」「资源」「class」三类汇总，支持「全部展开 / 全部折叠」及彩色状态标签。修改过 Java 文件时，请先完成编译并确认最新产物已出现在 class 清单中。

          
    
            
  1. 点击顶部「导出」，先在「导出前差异确认」中核对变更，确认无误后点击「继续导出」。
    2. 
            
  2. 如原包存在签名，在内置确认弹窗中选择签名处理策略。
    3. 
            
  3. 选择新包输出路径（保持原包的 .jar 或 .war 扩展名；禁止覆盖原包，也不可导出到工作区内部非 exports 目录）。
    4. 
            
  4. 导出过程先写入同目录临时文件，通过结构校验后才原子发布；完成后可在「更多 → 项目历史与校验」查看校验明细。
    5. 
          

          
签名包门禁：已修改的签名包默认阻止保留失效签名，只有明确选择「移除失效签名」后才会导出未签名包；若生产环境要求签名，请按组织流程重新签名。

        


        

          
连接 JVM 与 Arthas 运行时工作台

          
打开「运行时工作台」，在顶部选择连接方式，加载目标 Java 进程后点击「连接 Arthas」。

          

            
本机 JVM 与 SSH 宿主机 JVM

            
本机模式直接点击「加载 Java 进程」。Linux 宿主机模式先选择 SSH 服务器，两种模式都可直接选进程。Attach 需要对应的完整 JDK。Linux 宿主机的 SSH 账号需与应用的有效 UID/GID 匹配。

            
SSH Windows JVM

            
使用目标 JVM 的运行账号登录 Windows SSH，加载 Java 进程后连接 Arthas。该账号需能运行 pwsh.exe（PowerShell 7），目标 JVM 需由完整 JDK 启动。方法追踪可从目标应用的原有入口触发。

            
已有 Arthas

            
选择本机回环或 SSH 转发，再填写 Arthas HTTP 端口与可选凭据。可以查类、看方法、反编译和检查 JVM。断开时结束工作台的本次连接，代理由原启动方管理。

            
SSH 认证与保存主机

            
「账号密码」模式使用内置 SSH 客户端，支持点击「保存主机」把密码经系统凭据加密存到本机，同一主机可按账号和端口保存多条，不需要时可「移除主机」；「OpenSSH 配置」模式填写本机 SSH 别名或 user@host。重启后首次连接仍需核对 SHA-256 主机指纹。

            
Docker 与 Kubernetes 环境

            
Docker 模式要求 SSH 账号具备 Docker 操作权限；切换到 Kubernetes 模式后，通过该 Linux 主机上的 kubectl 运行，可填写 Context、命名空间、标签选择器、可选调试容器名及远程 kubeconfig 路径（应用容器缺少 shell/JDK 时可借助同 Pod 共享进程命名空间的调试容器）。

            
连接与释放 Arthas

            
固定使用 Arthas 4.3.5 官方完整包并校验 SHA-256。内网无法访问下载站点时，可在「连接配置」选择同版 arthas-bin.zip。诊断结束后点击「释放 Arthas」。若 Windows JVM 仍占用代理 JAR，等目标 JVM 退出后重新加载进程即可回收。

          

        


        

          
日志、反编译与热替换 运行时工作台

          

            
应用日志

            
容器模式查看容器输出，SSH 宿主机模式填写 systemd 服务单元或日志文件绝对路径。可查看最近 1～1000 行，或实时追踪最多 5 分钟。本机日志可在应用控制台或应用配置的日志文件中查看。

            
类与方法查询、反编译与耗时追踪

            
在「类与方法」输入简单类名（自动模糊匹配）、完整类名（精确匹配）或 * 通配模式点击「搜索已加载的类」，点击搜索结果自动填入完整类名和 ClassLoader 哈希。「查看方法」支持按访问级别（public/protected/包可见/private）和方法类型（Spring HTTP 映射 / Java 接口 / 普通 / 代理类方法）组合筛选。「反编译」以只读方式展示线上源码；「追踪方法耗时」单次最多采集 20 秒或 3 次，启动后可切到「请求测试」触发调用。

            
Docker 容器热替换（在线编辑或上传 class）

            
连接 Docker 容器的 Arthas 后支持两种热替换方式：① 在「类与方法」点击「反编译并编辑」修改方法体，再点「编译并热替换」并选择对应的本地 Jar/War 解析依赖，工作台使用本地编译 JDK 编译验证、核对运行字节码并备份后执行热替换；② 在「环境与集成 → Docker 容器热替换」直接选择本地同名 .class 备份并替换。两种方式均可点击「恢复原 class」回滚，释放会话时也会尝试恢复。

            
JVM 检查

            
在「JVM 检查」页签一键获取「JVM 信息」「忙碌线程与堆栈」「内存」快照，耗时较长时可点「取消查询」。

          

          
热替换边界：基于 JVM 类重定义能力，仅适合修改方法体（单 class 补丁）；新增/删除字段或修改方法签名会被目标 JVM 拒绝。热替换只影响当前运行内存，不会改写容器磁盘上的部署包文件。

        


        

          
请求、对照、回归与性能 运行时工作台

          

            
请求测试与关联日志

            
在「请求测试」选择目标 JVM 的监听端口、HTTP/HTTPS 协议与路径，请求从目标环境发往 127.0.0.1。发送后可点「添加到请求集合」。Docker 与 Kubernetes 模式支持按 Request ID、Trace ID 或时间窗口查看关联日志。

            
部署包对照

            
在「类与方法」点击「对照本地包」，工作台采集运行中 class 并与本地 Jar/War（含嵌套依赖与多版本条目）比对 SHA-256 摘要和两侧 CFR 源码差异。

            
回归验证

            
在「回归验证」管理请求集合（支持打开/保存 JSON，自动清理常见鉴权头；本次共用鉴权头填在「本次共用请求头」），支持 status、maxMs、contains、jsonEquals（JSON 指针如 /result/ok）断言。先跑「运行补丁前基线」，再跑「运行补丁后验证」，直观比较状态码、响应体与耗时变化。

            
性能采集与导出诊断报告

            
在「性能采集」录制 5～30 秒的 JFR 或 火焰图（CPU 定时器 / CPU perf / Wall clock），完成后可保存为文件。点击页签栏右侧「导出诊断报告」可生成结构化 JSON 汇总报告（不含请求体、源码和日志原文）。

            
环境与集成

            
提供最多 20 个目标的「多实例检查」、复用当前业务端口的「Spring Boot Actuator」端点读取、「Loki 集中日志」LogQL 查询，以及从系统浏览器打开已有「Arthas Tunnel」控制台。

          

        


        

          
开发能力配置 仅管理员

          
点击顶部「开发能力」打开三标签页配置弹窗，每个标签前的状态点反映当前生效情况；修改后点击「保存并校验」。

          

            
编译 JDK

            
选择包含 bin/javac 的 JDK 根目录并保存校验，页面同步显示当前内置 JDK 版本。补丁编译的目标 Java 版本始终以原包 .class 为准。

            
Java 代码智能（Eclipse JDT LS）

            
勾选启用后，配置 JDT LS 解压目录与运行它的 Java 21+ JDK（仅用于运行语言服务器，不影响项目 Java 8/17 编译目标）。Win7 离线兼容包已内置 JDT LS 与 JDK 21，勾选启用且两项路径留空即可直接使用。

            
AI 代码助手

            
勾选启用后选择协议（OpenAI Responses API、OpenAI 兼容 Chat Completions 或 Anthropic 兼容 Messages API），填写完整地址或以 /v1 结尾的基础地址及模型 ID。本机回环和内网私有 IPv4（10/8、172.16/12、192.168/16）允许 HTTP 且无鉴权时可留空 API Key，公网端点须使用 HTTPS；Messages 协议可选择 x-api-key 或 Authorization Bearer。保存的 API Key 由系统安全存储加密保护，可勾选「清除已保存的 API Key」移除旧密钥。

          

          
只查看或修改 YAML、properties 等文本资源时，无需配置 JDT LS 或 AI，直接使用内置 Monaco 编辑器即可。

        


        

          
项目设置与工作区维护

          
以下低频与维护功能统一收纳在顶部右侧 「更多」 下拉菜单中：

          

            
项目设置（当前项目）

            
仅对当前项目生效。可查看只读的「目标 Java 版本」，自定义默认导出目录、可编辑单文件上限（1～100 MB）、无 BOM 文本默认编码、推荐嵌套 Jar 与界面偏好 JSON。

            
项目历史与校验（当前项目）

            
通过三个标签页分别查看「操作时间线」（带操作人与统一操作 ID）、「结构分析历史」与「导出校验历史」，方便回溯每次导入、编译与导出结果。

            
清理当前工作区 仅管理员

            
先预览工作区路径、文件数和占用空间，确认无误后删除磁盘工作区，但保留项目历史记录。存在运行中任务或预览后文件内容有变动时会拒绝清理。

            
扫描孤立工作区 仅管理员

            
扫描已完成导入但不再有项目记录的磁盘目录（如选择「仅删除历史」后遗留的目录），核对预览清单后统一释放磁盘空间。

          

          
清理前请核对成果：清理工作区会删除目录内的解压文件、源码与配置修改、编译产物以及保存在该工作区 exports 目录下的导出包，需要保留的包请先复制到工作区以外。

        


        

          
任务日志与排错诊断

          

            
任务状态与底部执行日志

            
导入、分析、编译和导出会先创建持久化任务并建立实时日志连接；耗时较长时可随时点击任务状态栏的「取消任务」。底部「执行日志」支持拖拽上边缘调整高度，并提供「复制」「清空」「收起」按钮。出现失败时请先记录失败阶段与首条具体报错。

            
错误排查向导（更多 → 错误排查向导）

            
汇总 JDK、CFR 反编译、编译、签名、路径与端口等常见异常的检查与处理步骤。例如遇到「找不到匹配的 JDK」，对照项目目标版本后在「开发能力」重新指定含 bin/javac 的 JDK 根目录并保存校验。

            
导出脱敏诊断（更多 → 导出脱敏诊断）

            
生成一份脱敏 JSON 诊断包（包含软件版本、系统与 Java 环境、近期任务日志与后端日志，不含敏感令牌），便于提交或协同排查问题。

            
启动失败诊断器（Windows）

            
若免安装包在打开界面前即退出，可将发布目录同级的 JarPatch-Startup-Diagnostics.exe 与主程序放在同一目录后双击运行，它会自动收集退出码、Chromium 日志与桌面启动日志并打开诊断报告目录。
