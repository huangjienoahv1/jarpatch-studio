# 运行时工作台顶部连接区重构设计文档

- 日期：2026-11-21
- 作者：黄杰
- 改动规模：小范围前端交互与布局重构（仅改动前端 4 个文件 + 同步 `readme.md`，不改动后端接口与 SSH/Arthas 协议逻辑）

## 1. 背景与目标

### 为什么改
原有运行时工作台顶部连接区将 15+ 个高/低频控件堆叠成 4 行：
- SSH 登录字段被割裂（`SSH 主机` 与 `容器 / 进程 / Arthas` 挤在第 2 行，`账号 / 端口 / 密码` 掉到第 3 行），操作动线呈 Z 字形。
- `已保存的主机 / 移除主机` 与 `保存主机` 分散在首尾两行；极低频的离线包与认证方式常年占位，挤压下方日志与代码区空间。
- 用户核心高频场景为**重复连接已保存的那几台服务器**，日常根本不需要看到完整登录表单。

### 目标（Goals）
- 日常 95% 场景顶部压缩为**单行工作条**，按自然操作顺序从左到右排列：`服务器 → 加载容器 → 容器 → Java 进程 → 连接/释放 Arthas`。
- 将主机管理（新增、改密、保存、移除）、认证方式（账号密码 / OpenSSH）、运行环境（Docker / Kubernetes 及 K8s 参数）和 Arthas 离线包收纳至可按需展开的**连接配置面板**，且面板内 SSH 字段聚合在一起，彻底消除 Z 字形填表。
- 打开工作台时按是否有已保存主机智能决定默认态（有保存主机则默认选中首台并收起配置面板；无保存主机则自动展开配置面板）。

### 非目标与反目标（Non-goals & Anti-goals）
- **不做**：不改动后端 HTTP/WebSocket API，不改动 `RuntimeWorkbench` / `RuntimeSshHosts` 底层存储格式，不引入新前端框架或高版本不兼容依赖。
- **避免（反目标）**：
  - 严禁切换服务器下拉框时自动发起 SSH 连接（防止误触连接线上服务器）。
  - 严禁丢失既有功能（OpenSSH 模式、Kubernetes 5 项参数、离线包选择与恢复、保存/移除主机、未保存源码弃改确认、清理未确认重试释放）。
  - 严禁使用 CSS `order` 打乱 DOM 与键盘 Tab 顺序。

## 2. 约束条件

- **运行环境兼容**：严格兼容现代 Electron 与 Windows 7 SP1 x64（Electron 22 / Chromium 108），不使用 Chrome 116+ 的原生 `popover` 或不兼容 CSS 特性。
- **双主题一致**：完整复用 `styles.css` 定义的深色/浅色 CSS 变量，保持按钮、边框、状态灯视觉一致。
- **无障碍与表单规范**：所有输入/下拉框关联可见 `<label>`；展开/收起按钮使用 `aria-expanded` 与 `aria-controls`；键盘回车连接需检查 `!event.isComposing` 防止中文输入法误触发。

## 3. 方案对比与选型

| 方案 | 概要 | 权衡 | 结论 |
| --- | --- | --- | --- |
| **方案 A（选定）** | **顶部单行工作条 + 页内可展开连接配置面板** | 日常只有 1 行极度清爽；展开后字段分块工整；无嵌套弹窗；改低频配置需多点一次展开 | **采用**：最匹配“重复连已保存主机”高频场景，改动简单可控 |
| 方案 B | 单行工作条 + 二级独立管理弹窗 | 主界面同样清爽，但运行时工作台本身已是弹窗，弹窗套弹窗层级过深 | 放弃 |
| 方案 C | 上下两步常驻卡片（不折叠） | 理顺了顺序但仍常驻占两行，重复连已保存主机时冗余字段太多 | 放弃 |

## 4. 详细交互设计（方案 A）

### 4.1 标题栏（顶部）
- 左侧：图标 + `运行时工作台` 标题与简介。
- 右侧：
  - 轻量状态徽标区（仅在非默认配置时显示，如 `K8s`、`OpenSSH`、`离线包`，收起配置面板时仍一眼可见当前模式）。
  - `连接配置` 切换按钮（`#runtimeConnToggleBtn`，`aria-controls="runtimeConnectionBox"`，`aria-expanded` 同步状态，展开时文案变为 `收起配置` 并高亮）。
  - `关闭` 按钮（`#runtimeClose`）。

### 4.2 常驻单行工作条（`#runtimeQuickBar`）
按从左到右的自然动线排成单行（窄屏 `< 950px` 时自动平稳折行，不溢出、不竖排）：
1. **服务器选择器**（`#runtimeSshHosts`，标签 `服务器`）：
   - 列出全部已保存 SSH 主机（`user@host:port`）。
   - 若当前为临时输入主机或 OpenSSH 别名，顶部动态显示当前目标项（如 `OpenSSH · dev-ssh` 或 `临时 · root@10.0.0.5:22`）并选中，如实反映当前连接目标。
   - 列表底部提供 `＋ 新增 / 临时主机…` 选项：点击后清空表单、切换至账号密码模式、自动展开配置面板并聚焦 `SSH 主机` 输入框。
   - 切换已保存主机时**仅回填连接参数，不自动发起 SSH 连接**，仍由用户手动点「加载容器」。
2. **加载按钮**（`#runtimeConnect`）：Docker 模式显示 `加载容器`，Kubernetes 模式显示 `加载 Pod`。若当前未填写主机地址，点击时自动展开配置面板并聚焦主机框。
3. **竖向分隔线**：视觉区隔“连接主机”与“选择运行目标”。
4. **容器选择器**（`#runtimeContainer`，标签在 Docker 下为 `容器`，Kubernetes 下为 `Pod / 容器`）。
5. **Java 进程选择器**（`#runtimeProcess`，标签 `Java 进程`）。
6. **Arthas 主操作按钮**（互斥显隐）：
   - `!canRelease` 时：显示主按钮 `连接 Arthas`（`#runtimeAttach`），隐藏 `释放 Arthas`。
   - `canRelease` 为 `true` 时：隐藏 `连接 Arthas`，显示 `释放 Arthas`（`#runtimeDetach`），已连接显示绿色状态点，若处于清理未确认态显示警示色状态点。

> 注：由于单行工作条已常驻展示完整目标与状态，移除原先冗余的 `#runtimeConnSummaryBar` 折叠文字摘要条，避免展开/折叠来回切换的割裂感。

### 4.3 可展开的连接配置面板（`#runtimeConnectionBox`）
展开后位于单行工作条正下方，采用 `<fieldset>` + `<legend>` 分成 2 个清晰分组：

1. **分组一：SSH 服务器与认证**
   - 第 1 行网格：`SSH 认证`（`OpenSSH 配置` / `账号密码`） + `SSH 主机` + `SSH 端口`（仅账号密码模式显示）。
   - 第 2 行网格（仅账号密码模式显示，容器 `#runtimePasswordFields`）：`SSH 账号` + `SSH 密码` + `保存主机` + `移除主机`。
   - 所有 SSH 登录字段与「保存 / 移除」按钮紧邻同区，彻底告别 Z 字形操作；切到 OpenSSH 时自动收缩为极简 1 行。
2. **分组二：运行环境与 Arthas 包**
   - 第 1 行：`连接方式`（`Docker` / `Kubernetes`） + `Arthas 离线包`（`选择离线包` 按钮 + 包名状态 + 选中后出现的 `使用官方下载` 按钮）。
   - 第 2 行（仅 `Kubernetes` 模式显示，`#runtimeKubernetes`）：整齐网格排布 `Context`、`命名空间`、`标签选择器`、`调试容器名`、`远程 kubeconfig`。

### 4.4 默认展收策略
- 打开工作台且尚未建立连接时：
  - 若已有已保存主机：自动选中第一台主机并**默认收起**配置面板，打开即用单行工作条。
  - 若尚无任何已保存主机：**默认展开**配置面板并聚焦 `SSH 主机` 输入框。
- 成功「连接 Arthas」后：自动收起配置面板，把最大高度让给诊断与源码区。
- 成功「释放 Arthas」后：保持单行工作条可用，不强制撑开配置面板（用户随时可切容器或再点右上角「连接配置」）。

## 5. 影响文件范围

- `frontend/src/index.html`：重构 `#runtimeDialog` 顶部连接区 DOM 结构（单行工作条 + 两分组可展开配置面板，移除冗余摘要条）。
- `frontend/src/styles-runtime.css`：重写顶部工作条与配置面板样式（深浅双主题、Chromium 108 兼容、窄屏自适应）。
- `frontend/src/runtime-renderer.js`：更新展开/收起逻辑、服务器下拉框智能同步（含临时主机与「新增主机」入口）、首次打开默认选中首台保存主机、连接/释放 Arthas 互斥显隐、动态文案（Docker/K8s）、IME 安全回车及常量提取与完整注释。
- `frontend/src/runtime-integrations-renderer.js`：同步 K8s 切换时单行工作条标签与徽标联动。
- `readme.md`：更新「运行时工作台」章节的使用说明与反思记录。
